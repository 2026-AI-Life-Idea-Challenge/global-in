# B·C 상담 통합 — 2026-10-31

## 기준과 범위

`codex/bc-consult-integration`은 A #18 및 D #19가 병합된 `develop`에서 시작했습니다. 사용자의 B·C 수정 허용 이후 진행한 통합 변경입니다. 정책 원문·검토 상태·서비스 승인 플래그·임베딩 데이터는 변경하지 않았습니다.

## B 연결

- 기존 B의 프로그램 목록, 지원제도 목록·연결 조회를 현재 그래프에서 직접 사용합니다.
- 단일 프로그램은 `answer_program_question`, 넓은 탐색은 `answer_programs_question`, 선택한 지원제도는 `answer_support_question`으로 연결합니다.
- B의 인용·구조 검증과 근거 부족 상태를 유지합니다. 검색 실패·생성 실패를 ‘근거 없음’으로 숨기지 않습니다.
- 프로그램과 지원제도별 자격 검토·모집 상태·원문 출처를 분리해 반환합니다.
- 검색된 모든 구절을 답변 출처로 붙이지 않고, B 주장의 인용에 실제 연결된 구절만 사용합니다.
- 지원제도 목록만 반환된 경우 해당 프로필의 공식 출처를 표시합니다. 목록 연결을 자격 충족으로 취급하지 않습니다.
- 기존 B CLI 질문 라우터는 교체하지 않았습니다. 상담에서는 별도 B 해석 모델을 중복 호출하지 않습니다.

## C 흐름

- 프로필과 첫 메시지를 같은 POST에 받아 한 번의 그래프 실행으로 처리합니다. D의 선행 프로필 PATCH를 제거했습니다.
- 구조화된 프로필 PATCH는 입력 검증 후 재검토하며 사용자 이해 모델을 다시 호출하지 않습니다.
- 일반 탐색은 국적·생년월일 부재만으로 막지 않습니다. 개인 자격 확인에는 필요한 기본 정보를 추가 질문합니다.
- 나이·출생연도만으로 생년월일을 추정하지 않습니다. 정확한 날짜가 발화에 없으면 모델이 만든 날짜를 저장하지 않습니다.
- 추출 필드를 검증하고, 카탈로그에 없는 대상 ID를 거부합니다.
- 국가·유형이 바뀌면 이전 대상 선택을 정리하고, 생년월일 등만 바뀌면 명시적으로 선택한 대상은 유지합니다.
- A의 판정을 설명하기 위한 추가 LLM 호출을 제거했습니다. 요건별 상태·사유·근거 ID를 보존합니다.
- B의 근거 답변을 준비 단계의 새 LLM 요약으로 덮어쓰지 않습니다. 인용된 주장과 A 미확인·미충족 항목으로 확인 액션을 구성합니다.
- 확인 액션은 공식 필수 서류나 승인 완료로 표현하지 않으며, 근거 없는 마감·처리 기간·로드맵 순서를 생성하지 않습니다. 구체적 일정 로드맵은 이 변경에서 제공하지 않습니다.

## 상담 세션

- 실제 서버는 별도 로컬 SQLite 파일에 상담 상태를 저장합니다. 기본 경로는 `data/runtime/consultation.sqlite`이며 `CONSULT_SESSION_DB`로 변경할 수 있습니다.
- 동일한 파일을 사용하는 워커 간에는 토큰 기반 lease로 같은 세션의 중복 실행을 차단합니다. 오래된 워커는 새 결과를 덮어쓰거나 새 잠금을 해제할 수 없습니다.
- 기본 만료는 마지막 상태 저장 기준 24시간, 실행 lease는 10분입니다. 만료 세션은 새 상담 생성 시 정리합니다.
- 서버 재시작 후에도 새 저장소에 기록한 프로필·이력을 복원할 수 있습니다. 이전 메모리 전용 세션은 자동 이관되지 않습니다.
- 이 방식은 같은 로컬 파일을 공유하는 배포 범위입니다. 다중 호스트, 사용자별 인증·소유권 분리, 암호화·운영 보관 정책까지 완료한 것은 아닙니다.
- 세션 저장 파일은 Git에서 제외합니다. 정책 PostgreSQL과 분리되어 있습니다.
