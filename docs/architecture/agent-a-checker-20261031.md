# A 전용 평가기 정합성 수정 — 2026-10-31

## 문제와 변경

A 전용 checker는 DB의 `definition`을 조건식으로 바로 평가했습니다. 실제 DB에는 `expression`, 대상, 검증일, 적용 기간 등이 포함된 전체 요건 정의가 저장돼 있습니다.

- 전체 정의를 공통 `evaluate_requirement`에 전달해 조건식과 근거 시점을 함께 검사합니다.
- 기존 테스트·호출자가 전달하는 단독 조건식도 호환하되 부분 범위를 전체 충족으로 집계하지 않습니다.
- 규칙 집합의 예상 요건 ID를 기준으로 평가하고 누락을 UNKNOWN으로 표시합니다.
- 대상·릴리스·식별자 불일치와 중복 요건은 UNKNOWN으로 처리합니다.
- `coverage_complete=False`이면 모든 반환 조건이 PASS여도 전체 PASS로 승격하지 않습니다. 확인된 필요조건의 FAIL 집계 동작은 유지합니다.
- 공통 평가기의 중첩 AND·OR가 tuple 컨텍스트를 list와 결합하면서 발생하던 TypeError를 수정했습니다.
- 결과에 UNKNOWN 사유를 보존합니다. DB·규칙 정의를 변경하지 않습니다.

## 검증

- 전용 checker 계약 테스트, 기존 규칙·재검토 및 A–C 연결 회귀 테스트 수행
- 공통 평가기 24개와 근거·심사 경계 테스트 16개 통과
- 실제 DB 읽기 전용 검증: 52개 대상 × 2개 기준일(2026-10-28, 2026-10-31) = 104회 평가, 요건별 결과 1,182개, 빈 대상 0개
- 입력 프로필은 빈 테스트 프로필입니다. 개인 자격 충족이나 현재 법률의 최신성 확정을 의미하지 않습니다.
- B·C 담당 코드, D 화면, DB 데이터, 임베딩 및 유료 API는 변경·실행하지 않았습니다.

D 상태 처리 후속 변경과 별도의 A 브랜치 커밋·PR로 제공합니다. 자동 병합하지 않습니다.
