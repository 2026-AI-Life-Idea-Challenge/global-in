# 전체 카탈로그 품질·세션 운영 보완

## 완료한 범위

- 현재 DB의 40개 프로그램·12개 지원제도, 5개 국가 전체를 실제 상담 그래프로 호출했다. 합성 한국인 프로필을 사용했다. 시나리오 제작·촬영·영상 녹화는 하지 않았다.
- 1차 52개에서 50개가 정상 응답했고, 모델의 잘못된 대상 ID·지원제도 의도로 2개가 실패했다. 별도 모델 평가가 182개 답변 문장 중 22개를 지적했다. 이 지적에는 평가 모델의 과도한 판정도 포함되어 있다.
- 보완 후 전체 52개가 HTTP 200, 대상 ID 일치로 응답했다. 170개 답변 문장 중 별도 평가가 2개를 지적했다. 연령 경계 표현과 조건 없는 목록의 의무 해석을 추가 보완했다. 캐나다 워홀의 빈 답변 1건도 별도로 수정하고 후속 실제 상담에서 답변 생성을 확인했다.
- 평가 지침도 보정했으므로 위 문장 수를 동일 기준의 정확도 개선율로 계산하지 않는다. 이 검사는 저장된 인용 구절과의 일치 평가이며 법률의 현재 정확성에 대한 승인이나 독립 전문가 감사가 아니다.

## 답변 생성 변경

1. 사용자 이해 단계의 의도·프로그램·지원제도 ID는 JSON Schema의 허용 값으로 제한한다. 프로필 변경은 명시된 필드 목록으로 추출한다. 잘못된 ID가 발생해도 임의의 비슷한 프로그램에 연결하지 않는다. 현재 사용자 발화의 정확한 공식 이름으로 복구할 수 없으면 추가 질문한다.
2. 특정 비자 질문이 지원제도 범위로 분류되어 빈 답변이 생기는 경우를 보완했다. 지원금 질문은 별도로 유지한다.
3. 호주 417·462 단계 변경에서 가장 최근 사용자 선택을 사용한다. `첫 신청 말고 2차`에서 부정된 첫 신청을 다시 선택하지 않는다.
4. 인용 구절 분리가 IELTS 4.5, 사진 3.5cm, 법령 5.17 같은 숫자 중간을 자르지 않도록 수정했다.
5. 상담 그래프에서는 생성 뒤 별도 모델 요청으로 답변과 해당 인용 구절을 다시 대조한다. 요건·숫자·연령 방향·국적·예외·의무를 확인하고 뒷받침되지 않는 항목은 보류한다. 검사 누락·실패 시 검증되지 않은 답변을 그대로 내보내지 않는다. `CONSULT_VERIFY_GROUNDING=0`은 명시적인 진단용 해제이며 권장 기본값은 활성화다.
6. 모델의 `answer=null`과 인용 배열 같은 구조 불일치는 상담 흐름에서만 한 번 재생성한다. 네트워크 오류를 무제한 재시도하지 않고, 최종 응답은 기존 검증을 다시 통과해야 한다.
7. 생성 지침의 한국어 용어·존댓말·연령 경계·조건/면제 범위를 보완했다. 화면에서 검색 근거 구절을 펼쳐 볼 수 있고, 요건 설명과 기관에 확인할 질문도 표시한다.

별도 근거 대조는 추가 호출 비용·지연을 발생시키며 모델 평가 자체도 오류를 낼 수 있다. 모든 문장의 참·거짓을 증명하는 장치는 아니다.

## 다중 턴 검증

일본 워홀의 프로필 변경, 호주 417 첫 신청→2차→후속 질문, 캐나다→독일 유학 변경, 미국 H-1B의 지침 무시 요청→F-1 변경, 지원금의 현재 접수·최종 승인 요청, 호주 190 재확인을 검사했다.

- 16턴 중 15턴이 처음 통과했다. 지원금 후속 질문의 구조화 출력 불일치는 1회 제한 재생성을 추가한 뒤 해당 3턴을 재호출하여 모두 통과했다. 국가/대상 범위, 프로필 PATCH 반영, 최종 승인 단정 방지를 확인했다.
- 두 평가 프로세스가 로컬 검색 모델을 동시에 불러오던 초기 실행은 Windows 메모리/페이징 부족으로 실패했다. 해당 실패를 성공으로 집계하지 않았다. 단일 검색 모델 프로세스로 재실행했다. 제한된 RAM에서는 평가 실행과 여러 API 워커에 모델을 중복 적재하지 말아야 한다.
- 이 검사에서 날짜 변경이 반영되어도 원본 규칙의 시점 검증/기관 확인이 남아 있으면 자격 결과는 `추가 확인 필요`로 유지된다. 생성 모델의 일반 요건 설명으로 A의 판정을 임의 변경하지 않는다.

## 세션 소유권·공유 저장소

- 프론트 서버가 HttpOnly·SameSite=Strict 쿠키를 발급하고 서버에서 소유권 값을 HMAC으로 계산해 내부 API로 전달한다. 상담 ID만 안다고 다른 브라우저에서 접근할 수 없다. POST/PATCH 모두 소유권을 확인하며 다른 소유권에는 404를 반환한다. 기존 소유권 없는 세션은 새 상담으로 시작해야 한다.
- 외부 Origin의 상담 변경 요청은 403으로 차단한다. HTTPS 운영 환경의 쿠키에는 Secure를 설정한다. 프록시 뒤에서는 `CONSULT_PUBLIC_ORIGIN`을 외부 HTTPS Origin으로 설정한다. 모든 프론트 복제본은 동일한 `CONSULT_OWNER_SECRET`(미설정 시 내부 API 키)을 사용해야 한다.
- PostgreSQL 세션 구현은 DB 서버 시계·행 잠금·토큰 임대를 사용한다. 모델 실행 중에는 DB 트랜잭션을 유지하지 않는다. 만료된 작업은 새 임대의 상태를 저장하거나 잠금을 해제할 수 없다.
- 격리된 로컬 PostgreSQL에서 독립 연결 8개 워커·64개 합성 세션을 검증했다. 상태 공유·동시 진입 차단·다른 소유권 차단·오래된 저장 차단·오래된 해제 차단이 통과했다(4.16초). 합성 세션은 삭제했고 테스트 서버는 종료했다. 실제 다중 호스트 지연·운영 트래픽 부하를 측정한 결과는 아니다.
- 동시 그래프 실행은 워커당 기본 4개로 제한하고 초과 요청에는 503·Retry-After를 반환한다. 한 상담의 중복 실행은 409다. 해석·생성·근거 대조는 기본 100초의 공통 시간 예산을 사용한다. 실패 턴은 저장하지 않는다.
- 세션에는 프로필·최근 20개 메시지·대상 ID·범위만 저장하며 매 턴 전체 카탈로그/검색 근거를 복제 저장하지 않는다.

## 현재 적용 상태와 공유 DB 활성화

현재 프로젝트의 DB 계정은 새 스키마 생성 권한이 없어 운영 DB에 세션 스키마를 만들지 않았다. 기본 SQLite에 소유권·동시성 보완은 적용되며, 공유 PostgreSQL은 구현·격리 검증까지 완료한 상태다.

별도 세션 DB에서 스키마 생성 권한이 있는 연결을 사용해 초기화한다. 정책 DB의 테이블을 변경하지 않는다.

```powershell
# 실제 연결 문자열은 비밀 환경설정으로 관리한다.
$env:CONSULT_SESSION_DATABASE_URL='postgresql://SESSION_USER:PASSWORD@HOST:5432/SESSION_DB'
.\.venv\Scripts\python.exe scripts/evaluate/consultation/check_shared_sessions.py --initialize --requests 64
```

API 서버의 모든 인스턴스에도 같은 `CONSULT_SESSION_DATABASE_URL`을 설정한다. 운영 런타임 역할은 `consult_runtime.sessions`의 조회·삽입·수정·삭제 권한과 스키마 사용 권한만 부여하는 것이 적절하다. 연결 설정이 없으면 기존 SQLite가 사용된다.

현재 서비스에는 계정 로그인 시스템이 없다. 이번 브라우저 소유권 격리를 로그인 계정 인증·기기 간 계정 세션 연동이라고 표현하지 않는다. 계정 인증을 추가하면 검증된 계정 ID에 소유권을 연결하고 로그인/로그아웃 경계에서 세션을 분리해야 한다.

## 검증과 실행 기록

- Python 전체 264개 + 223개 subtests 통과. 기존 경고 4개.
- TypeScript 및 webpack 프로덕션 빌드 통과. ESLint 오류 0개, 기존 이미지 경고 3개.
- 프록시·SSR 11개, 실제 Chromium 조작 17개 통과. 영상 없음.
- 원문 실행 로그는 `data/processed/quality/consultation/`에 로컬 저장하며 Git에서 제외한다. 초기 실패·중간 결과·재검증을 구분한다.
- 재현 스크립트: `run_catalog_quality.py`, `run_multiturn_quality.py`, `check_shared_sessions.py`.
- 정책 DB 쓰기, 데이터셋 임베딩 생성, 법률·자격 승인 플래그 변경 없음. 실제 검색에는 기존 로컬 모델의 질의 벡터 추론을 사용했다.

## 확정하지 않는 부분

기관의 최종 심사·실시간 접수 여부·개인 최종 발급/선정은 근거와 권한 없이 확정하지 않는다. 대신 요건·미확인 사항·기관 확인 질문·공식 URL을 구체적으로 제공한다. 전체 카탈로그의 유한한 테스트 완료를 모든 미래 질문·모든 법률 변경에 대한 무오류 보장으로 표현하지 않는다.
