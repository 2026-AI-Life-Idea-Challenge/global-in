# frontend

Global-In의 사용자 인터페이스(UI)를 구현하는 디렉터리입니다.

현재 Frontend는 Streamlit을 사용하며,
사용자가 온보딩을 진행하고 AI와 대화하며,
추천 결과·자격 검토·공식 근거·체크리스트·Roadmap 등을 확인할 수 있도록 구성합니다.

Frontend는 비즈니스 로직을 직접 처리하지 않고,
FastAPI Backend를 통해 Agent 및 Service 기능을 호출합니다.

---

## 주요 역할

`frontend/`는 다음 기능을 담당합니다.

```text
사용자 입력
   ↓
Streamlit UI
   ↓
FastAPI Request
   ↓
Backend / Agent 처리
   ↓
Response 수신
   ↓
결과 화면 표시
```

Frontend는 다음 역할에 집중합니다.

```text
입력 UI
대화 UI
결과 표시
사용자 상태 표시
비교 결과 표시
Checklist / Roadmap 표시
공식 출처 표시
```

## 현재 구현

현재는 Streamlit 실행 확인을 위한 최소 화면이 구현되어 있습니다.

파일:

```text
frontend/app.py
```

현재 화면:

```text
Global-In
해외 진출 경로 탐색 AI 서비스
Frontend is running
```

현재 단계에서는 Streamlit 실행 여부를 확인하기 위한 기본 구조입니다.

## 온보딩 UI

사용자의 기본 해외 진출 조건을 파악합니다.

예상 입력 정보:

```text
나이
국적
현재 거주지
학력
전공
경력
언어 능력
희망 국가
진출 목적
희망 시기
```

처음부터 모든 정보를 강제로 입력하게 하기보다는,
기본 정보만 수집하고
필요한 정보는 상담 과정에서 추가 질문을 통해 보완할 수 있도록 구성합니다.

---

## AI 상담 UI

사용자가 자연어로 질문할 수 있는 대화형 인터페이스를 제공합니다.

예:

```text
독일로 취업하고 싶은데 어떤 방법이 있어?
```

```text
일본 워킹홀리데이 가능한지 확인해줘.
```

```text
캐나다 유학을 준비할 때 받을 수 있는 지원이 있어?
```

사용자의 질문은 FastAPI의 Chat Endpoint를 통해 Backend로 전달합니다.

---

## Agent 추가 질문

사용자 정보가 부족한 경우
Agent가 추가 질문을 생성합니다.

예:

```text
관련 경력은 몇 년인가요?
```

```text
현재 최종 학력을 알려주세요.
```

```text
희망 출국 시기는 언제인가요?
```

Frontend는 이러한 질문을 일반 AI 메시지처럼 사용자에게 표시하고,
답변을 다시 Backend로 전달합니다.

## 사용자 Profile UI

현재까지 확인된 사용자 정보를 보여줄 수 있습니다.

예:

```text
희망 국가: 독일
진출 목적: 취업
학력: 학사
전공: 컴퓨터공학
경력: 1년
언어: 영어 / 독일어
```

대화 과정에서 정보가 변경되면 Profile 화면도 갱신합니다.

---

## 진출 경로 추천 UI

추천 결과에는 단순히 프로그램 이름만 보여주지 않고
다음 내용을 함께 표시합니다.

```text
진출 경로
실제 프로그램
추천 이유
사용자 조건과의 관계
자격 검토 상태
연결 가능한 지원제도
추가 확인이 필요한 사항
```

예상 표현:

```text
경로 A
독일 취업 관련 프로그램

추천 이유:
- 사용자의 전공과 관련성이 높음
- 현재 학력 조건과 일치
- 관련 지원제도 존재

자격 상태:
추가 확인 필요
```

## 국가 / 경로 비교 UI

여러 후보를 비교할 때
표 또는 카드 형태로 보여줄 수 있습니다.

예:

```text
                 일본        독일        캐나다

진출 목적        취업        취업        취업
자격 상태        충족        확인 필요   미충족
경력 조건        ...         ...         ...
언어 조건        ...         ...         ...
지원제도         ...         ...         ...
```

실제 비교 항목은 데이터 구조에 맞춰 조정합니다.

## 자격 검토 결과 UI

Rule Evaluator의 결과를 사용자에게 이해하기 쉽게 표시합니다.

기본 상태:

```text
조건 충족
조건 미충족
추가 확인 필요
```

항목별 결과 예:

```text
국적
조건 충족

학력
조건 충족

경력
조건 미충족

예외 조건
추가 확인 필요
```

전체 결과만 보여주는 것이 아니라,
어떤 조건에서 해당 결과가 나왔는지 보여주는 것을 원칙으로 합니다.

---

## 비자와 지원제도 결과 구분

비자·체류 프로그램과 지원제도는 서로 다른 자격을 가질 수 있으므로
Frontend에서도 결과를 구분합니다.

예:

```text
비자 자격
→ 조건 충족

한국 지원제도 A
→ 추가 확인 필요

독일 지원제도 B
→ 조건 미충족
```

사용자가 하나의 결과를 전체 자격으로 오해하지 않도록 합니다.

## 공식 출처 UI

핵심 조건에는 가능한 한 공식 출처를 함께 표시합니다.

예:

```text
공식 기관
원문 제목
원문 URL
원문 업데이트일
Global-In 확인일
```

예상 표시:

```text
출처
- 기관: Example Immigration Agency
- 문서: Official Visa Guide
- 확인일: 2026-10-17
```

URL은 사용자가 직접 공식 원문을 확인할 수 있도록 제공합니다.

## Evidence 상태 표시

예:

```text
추가 확인 필요
```

```text
현재 공식 근거에서 명확하게 확인되지 않은 항목입니다.
해당 기관에 추가 확인이 필요합니다.
```

## Checklist UI

선택한 진출 경로의 준비 항목을 Checklist로 제공합니다.

예:

```text
[완료] 여권 준비
[준비 필요] 언어 성적 준비
[준비 필요] 경력 증명서
[추가 확인] 재정 증명 요건
```

상태:

```text
완료
준비 필요
추가 확인
```

사용자가 진행 상황을 쉽게 확인할 수 있도록 합니다.

## Roadmap UI

전체 준비 과정을 단계별로 보여줍니다.

예:

```text
1. 자격 확인
2. 언어 및 경력 조건 준비
3. 필요 서류 준비
4. 지원제도 신청
5. 비자 / 프로그램 신청
6. 승인 후 출국 준비
7. 입국 후 행정 절차
```

사용자의 현재 상태에 따라
완료된 단계와 다음 행동을 구분해서 보여줍니다.

## 신청 기간 표시

지원제도나 프로그램에 공식적인 신청 기간이 존재할 경우
확인된 범위에서 표시합니다.

예:

```text
신청 기간
2026-03-01 ~ 2026-04-30

정보 확인일
2026-10-17
```

현재 신청 가능 여부를 확인하지 못한 경우:

```text
현재 접수 여부 추가 확인 필요
```

처럼 표시하고 임의로 신청 가능하다고 표현하지 않습니다.

## Backend와의 관계

Frontend는 Agent나 DB를 직접 호출하지 않습니다.

```text
Streamlit
   ↓
FastAPI
   ↓
LangGraph / Services
   ↓
PostgreSQL / pgvector / LLM
```

즉:

```text
Frontend
→ 사용자와 상호작용

Backend
→ 실제 처리
```

로 역할을 분리합니다.

---

## API 호출 예시

향후 Chat 요청은 다음과 같은 흐름으로 구현할 수 있습니다.

```text
Streamlit
   ↓
POST /chat
   ↓
FastAPI
   ↓
LangGraph
   ↓
Chat Response
   ↓
Streamlit
```

Frontend에서는 Python의 `requests` 또는 `httpx` 등을 이용해
Backend API를 호출할 수 있습니다.

## UI 구현 원칙

- 사용자에게 내부 기술 용어를 과도하게 노출하지 않음
- 조건 충족 여부를 명확하게 표시
- 추가 확인이 필요한 정보는 확정적으로 표현하지 않음
- 비자 정보와 지원제도 정보를 구분
- AI 추천과 공식 규정을 구분
- 핵심 조건에는 공식 출처 제공
- 원문 URL을 사용자가 확인할 수 있도록 제공
- 긴 공식 문서는 요약하되 출처를 유지
- Checklist와 Roadmap은 현재 사용자 상태에 맞게 표시
- Mobile에서도 기본 사용이 가능하도록 단순한 Layout 유지

## 오류 처리

Backend 요청 실패 시
사용자에게 내부 Stack Trace를 그대로 노출하지 않습니다.

예:

```text
정보를 불러오는 중 문제가 발생했습니다.
잠시 후 다시 시도해주세요.
```

공식 정보 검색에 실패한 경우:

```text
현재 공식 근거를 확인하지 못했습니다.
```

처럼 정보 부족 상태를 명확하게 안내합니다.
